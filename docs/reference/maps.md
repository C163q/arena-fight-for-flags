# 2–8 人地图设计

用户已明确：需要覆盖 2–8 人的地图、运行时读取地图，且地图边界全部封住。这里按一人控制一支三棋子队伍设计。文件格式选择 RON；默认布局为地图 v2，已进行全基准自战和独立种子验证；正式比较不同 AI 仍需轮换位置并重复多次，不保证完全公平。

开局立即有旗的点数由规则 `max(1,(N+1)/3)` 计算，N 为旗点数、`/` 为整数除法，不在 RON 中重复配置；具体哪些点有旗由本场引擎种子随机决定。其余点默认等待 5–15 回合，在移动后首次尝试生成。

各图最外圈全部为 `#`。出生中心沿菱形等曼哈顿半径分布，每队朝中心方向放置一个近旗点，另加中央旗点。旗点都是中立资源；没有对应队伍独占规则。旧版中央方形障碍环已移除，改为约 4% 稀疏独立单格掩体，不限制到四个中央入口。生成器保护出生区周边与中央旗区，增加障碍不改变各出生区到各旗点的最短路距离。

[地图概览](../assets/maps-v2.svg) 与 [数值标定报告](../reports/map-balance-2026-10-13.md) 展示布局、几何数据、全基准对局和位置偏好。`python3 scripts/generate_maps.py --check` 验证静态 RON 与固定生成参数一致；不加 `--check` 会按参数重写默认地图，因此修改默认布局时同步生成器。运行时仍只加载 RON，不调用生成器。

## RON v1 数据契约

每张地图是一个顶层结构，资产中的完整样例可直接阅读。字段如下：

| 字段 | 类型/约束 |
| --- | --- |
| `format_version` | 整数，目前为 1；不支持的版本拒绝加载 |
| `id` | 非空 ASCII 标识符，当前使用 `arena_Np`；不能用于未经校验的文件路径拼接 |
| `players` | 2–8；等于本场队伍数 |
| `match_limits` | `target_score` 与 `max_turns` 均为正整数；分别为目标分和最大回合数 |
| `width`, `height` | 正整数；首版限制为 9–128，避免无界内存与 AI 工作量 |
| `terrain` | `height` 个 ASCII 字符串，每行恰有 `width` 个字符；仅允许 `#` 和 `.` |
| `spawn_regions` | 恰好 `players` 条，每条包含 `team_id, x, y, width, height`；宽高均为 3 |
| `flag_points` | 至少一个，最多 32 个；每条包含 `id, x, y`，ID 与坐标分别唯一 |

示例片段为结构说明，`terrain` 必须在真实文件中写出全部行：

```ron
// 实际完整文件见 maps/arena_2p.ron。
// 出生区和旗点由独立字段指定，不写进 terrain。
// spawn_regions 中的一条：
(team_id: 0, x: 18, y: 13, width: 3, height: 3)
// flag_points 中的一条：
(id: 0, x: 12, y: 12)
```

坐标左上原点，x 向右、y 向下。出生区 `x,y` 表示左上角，覆盖 `x..x+3`、`y..y+3` 的半开区间。它是地形之上的标记，其九个底层格必须都是 `.`。旗点同样独立于地形，旗点上的旗帜由游戏引擎管理，不能在地图文件中提前写死亡、血量或随机刷新结果。

## 运行时加载流程

1. runner 根据显式地图路径读取 UTF-8 RON；文件大小上限 1MiB，不把地图编译进程序。
2. 反序列化为版本化 MapDefinition，拒绝未知字段和非法整数。解析错误带文件名及行/列；语义错误带字段或坐标。
3. 验证本场 AI 数为 2–8，且与 `players`、出生区数量一致；队伍 ID 必须恰为 `0..players-1`。
4. 验证所有尺寸、行长和字符；尤其逐格检查上、下、左、右四边都是 `#`，不是只检查四角。
5. 验证出生区不越界、不覆盖墙、不相交；旗点不越界、不在墙或出生区内，且 ID 和坐标唯一。
6. 使用正交 BFS 检查所有可行走格连通，至少保证每个出生区都能到达全部旗点；九格出生区自然留有不少于三个合法初始位置。
7. 验证成功才创建比赛状态。错误时拒绝开局，不自动补墙、删障碍或重排出生区。
8. 将原始 RON 保存为回放目录的 `map.ron`，将规范化地图保存为 `map.json`，记录选用的地图 ID 与内容摘要。

上述宽高、旗点数和文件大小上限是首版工程约束；若调整，加载器、API、AI 与导出器应共同遵循。虽然最外圈封住，引擎仍需校验越界动作，不能以封边代替内存边界检查。

## 公平性检查与后续修改

几何校验只证明能玩，不能证明平衡。需要计算每个出生区九格到每个旗点的最短距离、各出生区之间距离、狭口宽度，以及旗点的多路径可达性；再用相同 AI 在不同出生槽轮换对战，比较得分与胜率。

后续可以增加同人数多张地图，修改须保留封边与可达性，重新执行几何测量和自战；不要只改地图名而沿用旧回放或旧评测结论。

## 地图终局默认值

比赛直接读取 RON 的 `match_limits`，CLI 不覆盖。默认 2–8 队统一目标 20 分，最大回合依次 400/500/600/700/800/900/1000。采用 35 场全基准自战的最长达标时间留约 35% 余量、向上取百，并保证每多一队上限至少增加 100；最终又用两个独立种子共 14 场验证。完整结果和重现命令见 [标定报告](../reports/map-balance-2026-10-13.md)。旧比赛使用其目录里保存的原始地图和上限，不因默认资产改变而重写。
