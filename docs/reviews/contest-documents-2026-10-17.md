# 参赛文档第一轮审阅与改写

用户要求先复制文档，在副本中审阅和反复改写，以保留原文对照；待用户认可后再替换正式材料。审阅稿入口为 [文档对照表](../../packaging/contest-draft/README.md)，含参赛 README、四份参赛 docs 和场外 README。

## 核对范围与结果

核对 [题包维护要求](../guides/contest-kit.md)、原文、C 头文件、比赛接口规范，以及自测、统计、打包和播放器的当前实现。本轮由维护者逐项核对，没有启动额外审查 agent，也未运行新手读者试用。

原文总体遵守题包的披露边界，但把内部说明中的“候选、私有、真实 worker、冻结、快照、有界”等用语直接带给参赛者，缺少前置解释。第一轮改为说明使用者需要完成的动作、会得到什么结果，以及遇到问题去哪里看。并修正回放用语：网页选项是“回合开始／回合结束”，`START/END` 是文本记录中的标记。

- 30 个本地链接通过检查；仅存在于题包中的头文件和播放器路径按最新题包文件清单核对。

由于本轮只增补审阅用文档，正式模板、打包器、二进制和题包均未修改，不重跑产品 release 构建、整场对战或仓库外题包实战验收。题包单元测试中的微型构建夹具仍按测试原有流程运行。以后正式替换时，应按题包指南检查、生成新的分发版本。

## 首轮用户反馈后的修改

用户指出退出码、分组排名、重复运行记录的含义不清楚，并要求明确初始化字段的实际数值、旗帜生成时间，以及使用“时间限制、内存限制”而非“预算、优惠”等说法。

- 自测稿解释退出码是程序结束时交给操作系统的整数；手动测试读报告即可，需要自行写脚本时再使用退出码。
- 用 A、B 双人和 A、B、C 三人的例子说明每组名单分别排名，不把这些开发自测合成总榜。
- 解释未完成的比赛续跑时会从头重跑，旧记录保留；通过计划报告的“回放索引”找到实际采用的完整记录。
- 核对 `crates/ai-worker/src/lib.rs`：初始化字段 `decision_budget_us` 始终为 `50000`，实际时间限制由比赛回合号决定。接口稿将字段数值与首回合 250ms 的规则分开说明，增加第 20 回合重启仍为 50ms 的例子。
- 明确不可见的是旗帜未来的生成回合；接口与规则审阅稿中不再使用“预算”，也不使用“优惠”描述首回合限制。

本次仅修改文档副本与审阅记录，未改变接口或程序行为。逐项与当前实现核对，并检查文档差异、链接、命令示例语法及正式模板未变；未重新运行比赛或构建题包。此前 11 项题包测试的结果属于第一轮检查，不作为本次重新运行的结果。
