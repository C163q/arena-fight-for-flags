# 人类计时器与 LLM 只读查询器

状态：设计待确认，尚未实现。用户已确认到达 `99:59:59` 后保持运行，显示和查询结果固定为上限，直到人手动退出。本文的程序名为拟议接口。

## 两个程序

新增一个 Rust workspace 包，构建两个独立可执行程序：

- `fff-timer`：人类手动启动，从 `00:00:00` 正向计时，在终端显示大字数字和冒号。前台运行，Ctrl+C 或 SIGTERM 退出；正常退出恢复显示。没有暂停、继续、重置、预设起始时间或后台启动选项。
- `fff-timer-query`：每次执行只查询一次。运行中时 stdout 仅一行 `HH:MM:SS`，末尾换行，退出码 0；不存在时 stderr 一行中文提示，stdout 为空、退出码 1。不提供启动、停止、暂停、重置或修改上限的入口，不自动启动计时器。

程序参数错误单列诊断并返回非零，不向正常查询结果附加日志、JSON、PID 或说明。LLM 使用查询器，人类负责计时器生命周期；这不改变 AI 单回合 50ms 的既有预算。

## 计时规则

采用 Linux `CLOCK_BOOTTIME` 单调时钟，时间不受系统日期修改影响，机器休眠所经过的时间计入。每次成功启动都记录新的起点，计算真实经过秒数，向下取整为完整秒，不通过循环次数累加计时。

显示值为 `min(经过整秒数, 359999)`，格式固定两位小时、分钟、秒。到达上限不退出、不回卷；内部起点保持不变。退出后查询提示不存在；下次启动重建起点，不恢复之前的数值，不提供历史或续跑功能。

两程序使用同一换算方式；查询返回查询瞬间的当前时间。终端按秒刷新，刚跨秒时屏幕可能尚未刷新，不把上一帧显示值当作权威时钟。

## 单例与只读通信

首版与现有项目一致面向 Linux。按同一运行系统的共享 `/tmp` 文件系统实施跨目录、跨登录用户的单例，使用固定的 `/tmp/fff-session-timer-v1` 文件，不使用项目目录、当前工作目录、用户目录或可配置命名空间来分隔实例。容器若隔离了 `/tmp` 则属于另一运行环境；本设计不要求跨隔离环境协调。

推荐 **内核记录锁加只读起点记录**：计时器打开固定文件并获取独占 POSIX 记录锁，保留描述符直至退出。再次启动若锁被占用立即拒绝，不能接管或重置已有计时器。正常退出、崩溃或 SIGKILL 都由内核释放锁。文件保持原 inode，不在退出时删除或通过 rename 替换，避免破坏单例。

首次创建时设置跨用户可访问的文件权限；已有文件通过不带 `O_CREAT` 的打开方式使用，避免 sticky `/tmp` 的现存文件保护干扰。拒绝符号链接、非普通文件和硬链接，不自动改写未知格式的文件。仅计时器获得锁之后写入版本、PID 和单调起点。

查询器只用只读描述符读取，通过 `F_GETLK` 检查真实持锁进程，不试图获取、释放或修改任何锁，不写文件、不发信号、不连接控制服务。旧文件尚在但无人持锁仍视为计时器不存在，不能仅根据文件或 PID 存在判断活性。

初始化使用可查询的独立锁范围区分未就绪与已发布状态。查询前后检查锁所有者、就绪状态和记录一致性，避免退出/重启交界读取旧起点。短暂初始化或切换时有限重试，仍不稳定则 stderr 给出未就绪提示并非零退出，不伪造时间。

另外两种方案：Unix socket 查询服务能在运行中直接返回时间，但增加监听、连接与客户端处理；每秒写时间文件比较直观，但增加写入和陈旧数值问题。本方案记录起点后不持续写文件，查询也不依赖计时器事件循环处理请求。

## 终端显示

使用内置块状字形绘制六位数字与两个冒号，风格接近用户给出的大字示例。只在 stdout 是终端、终端支持定位且当前宽高能放下完整大字布局时绘制；根据尺寸选择合适缩放并居中，不截断数字。

空间不足、尺寸无法获取或 `TERM=dumb` 时显示基本 `HH:MM:SS`；窗口调整后重新选择布局。成功运行但 stdout 非终端时，stdout 和 stderr 都保持静默，不输出 ANSI 控制符或周期性日志，仍计时、持锁且可查询。关闭/损坏的输出连接按无显示运行处理，不因管道断开而停止计时。

计时器不改变终端输入模式，不需要暂停/继续按键。信号退出仅请求主循环收尾，实际清理由常规代码执行；正常终端退出后恢复屏幕/光标，不在信号处理器执行复杂 IO。SIGKILL 下单例锁和活性仍正确，不能承诺此信号下执行终端收尾。

## 验证和交付

- 计时边界：0、59/60 秒、59:59/01:00:00、99:59:59、超过上限；起点由测试控制，无需真实等待数日。
- 并发/活性：双启动竞争仅一个成功；不同目录同一实例；正常退出、SIGTERM、SIGKILL 后不存在；重启归零；残留文件和 PID 复用不能恢复旧计时。
- 只读查询：没有运行时不创建状态文件；运行时查询不改变内容、起点或锁；初始化/重启期间不输出旧状态；成功输出严格一行。
- 显示：大/小终端与运行中 resize；非 TTY 无输出但时间持续增加；关闭显示端仍可查询；正常退出终端收尾。
- 真实测试只使用测试自身启动的计时器，不停止人类已经启动的实例。单测使用内部临时路径和可控时钟，不为正式 CLI 暴露可绕开全局单例的路径或起点参数。
