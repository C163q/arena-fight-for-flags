# 陪练 AI 实施计划

> 执行方式：当前会话逐项实现，最后独立审查。使用 executing-plans 与 test-driven-development。

**目标：** 交付独立的强陪练库和可核验实测。
**架构：** 仅依赖公开 ABI；地图缓存 → 联合任务 → 战术候选/预测 → C ABI 输出。
**技术：** Rust 2024、现有 worker、Python selftest。
**设计：** [陪练 AI](../design/specs/2026-10-19-sparring-bot.md)。

## 约束与审查重点

不改变基准、规则、题包；不读取私有状态。128×128 地图内存受控，首回合 250ms、后续 50ms，故障重启无额外优惠。重点检查擦角遮挡、混队移动环、射击死亡掉旗、稀疏编号、最大地图与上下文重启。

### Task 1: 地图与预测

文件：`bots/sparring/{Cargo.toml,src/lib.rs,src/board.rs,src/forecast.rs}`、workspace 配置。

- [ ] 写几何与移动/死亡掉旗失败用例，运行确认缺失行为。
- [ ] 实现有界缓存 `Board` 与独立 `State` 预测，验证擦角、链、换位、同格冲突、先死亡掉旗再移动。
- [ ] 运行新库单测和 workspace 测试；提交。

### Task 2: 联合策略与生命周期

文件：`src/{lib,objectives,search,tests}.rs`。

- [ ] 写取旗返家、协同射击、携旗避旗、ABI 生命周期失败用例。
- [ ] 实现状态化 C ABI、旗点历史、联合分配、风险路径与有限预测搜索。
- [ ] 运行单测、fmt、clippy、真实预检；保存开发版本快照并提交。

### Task 3: 实战迭代与交付

文件：`docs/reference/sparring-ai.md`、实测报告、README、文档导航。

- [ ] 对基准、历史强提交做 2–8 队换位实战并验证记录，检查故障/非法/耗时。
- [ ] 如暴露规则错误先补失败测试；策略参数根据开发样本调整，另用留出条件验证。
- [ ] 完成使用文档与诚实的样本结论，执行完整检查，独立审查并处理重要问题。
- [ ] 提交并合并回主工作区，不推送远端。
