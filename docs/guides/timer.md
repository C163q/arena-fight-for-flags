# 人类计时器与 LLM 查询器

两个独立 Rust 程序用于 AI 设计/编码阶段的总用时计时，不改变对战决策预算（每队比赛第 1 回合 250ms，之后每回合 50ms）。面向 Linux，共享 `/tmp` 的运行环境中只有一个计时器。

## 构建和使用

```sh
cargo build --release -p fff-session-timer
```

由人类在一个终端手动启动：

```sh
./target/release/fff-timer
```

从 `00:00:00` 开始，大字显示数字与冒号；按 Ctrl+C 退出。另一个终端或 LLM 只执行查询器：

```sh
./target/release/fff-timer-query
```

成功时 stdout 严格只有一行，例如 `00:01:23`，退出码 0。查询不启动、停止、暂停、继续或重置计时器；两个程序都不接受参数，也不提供后台启动选项。

计时器未运行时，查询器 stdout 为空，stderr 提示“计时器不存在（未运行）”，退出码 1。再次启动正在运行的计时器也返回 1，不影响原实例。参数、权限、无效状态或持续未就绪等错误返回 2，并仅在 stderr 给出说明。

## 计时和显示

- 用 Linux `CLOCK_BOOTTIME` 计算从本次启动起经过的完整秒数，系统校时不会影响结果，机器休眠也计入。
- 达到 `99:59:59` 后保持运行，显示和查询都固定为这个上限，不回卷或自动退出。
- 退出后查询提示不存在；下次启动重新归零。没有恢复、暂停或历史计时功能。
- 终端空间充足时使用块状字形并居中；至少 41 列、9 行可容纳基础大字，较大窗口会选择更大的字形。运行中调整窗口大小会重新布局。
- 空间不足、尺寸未知或 `TERM=dumb`/未设置时使用普通 `HH:MM:SS`。非 TTY 时 stdout/stderr 都保持静默，计时和查询仍可用。
- 终端关闭或输出堵塞不会暂停计时；正常 Ctrl+C/SIGTERM 退出发送光标与画面恢复指令，暂时堵塞时最多额外等待约 250ms 并处理部分写入。输出持续不可写或已经关闭时只能尽力恢复，仍会及时退出。SIGKILL 不能执行终端收尾，但内核仍会释放单例锁。

显示按秒更新，窗口变化约每 100ms 检查；查询返回查询瞬间的完整秒数，刚跨秒时可能比上一屏画面快一帧。计时依据单调起点，显示刷新延迟不造成累计误差。

## 单例与只读约定

固定状态文件是 `/tmp/fff-session-timer-v1`，不随用户、仓库路径或当前目录变化，没有命令行或环境变量可改写路径。不同项目副本和登录用户共享这个位置；容器如果隔离了 `/tmp`，则属于另一运行环境。

计时器持有 POSIX 独占记录锁，起点发布前另有初始化锁区间。正常退出、崩溃或 SIGKILL 由内核释放锁；状态文件保留但不代表仍在运行。重启只在拿到锁后写入新的起点，不删除或替换 inode；不要手动删除运行中计时器的状态文件。

查询器只读打开文件，用 `F_GETLK` 查询锁和就绪状态，不获取/释放锁、不修改内容、不发信号，也不向计时器事件循环发请求。前后检查锁持有者、初始化锁与两次完整记录的一致性，切换期间有限重试；不能得到稳定值时返回非零，不把旧起点或残留 PID 当成当前计时。

PID 命名空间隔离不影响共享 inode 上的锁是否存在，但 `F_GETLK.l_pid` 可能为 0 或映射后的其他正数。记录中的 PID 仅作诊断，不能与查询方看到的锁 PID 比较。新查询器保持原三字段状态格式，可查询未重启的旧版计时器；旧查询器仍有这一兼容问题。

沙箱内外必须共享同一个 `/tmp` 状态 inode 和 `CLOCK_BOOTTIME` 时间基准。单独隔离 `/tmp` 或设置独立时间命名空间时，不保证可互查或得到正确时间，应由场外人员配置环境；查询器不自行绕过沙箱。

首次创建文件设置权限为 `0666` 供不同登录用户使用；已有文件不自动 chmod。文件权限受本机 `/tmp`、ACL 和系统策略约束。符号链接、硬链接、非普通文件、未知格式均拒绝，不自动覆盖或修复。

实现维护时注意：POSIX 锁按进程持有，关闭同一 inode 的任意描述符都可能释放本进程锁。计时器只持有一个状态描述符，不在自身进程调用查询逻辑；显示直接使用内存中的起点。查询器是独立进程。

## 验证

```sh
cargo test -p fff-session-timer
python3 tests/timer_integration.py --out runs/timer-check-new
# 宿主支持 unshare 用户/PID 命名空间时，强制验证沙箱查询：
python3 tests/timer_integration.py --out runs/timer-pidns-new --pid-namespace
```

Rust 单测另包含两个方向的真实 PID 命名空间查询；无法创建命名空间时会明确输出 SKIP，不能把它当作已覆盖。上述 `--pid-namespace` 验收要求环境支持，失败会报错而不静默跳过。

真实验收需要 release 二进制、PTY 与进程信号权限。它先确认没有既有计时器，只停止自己启动的进程；若人类已启动实例则拒绝执行，不接管或重置它。验收结束不留下计时器运行，状态文件可以残留。

单测用内部临时路径和时间输入验证整秒、进位、上限、独立进程争锁、初始化、旧状态、未知数据与特殊文件保护，不为正式程序暴露测试路径或预设时间。真实验收覆盖非 TTY 静默、时间前进、只读查询、跨目录单例、SIGINT/SIGTERM/SIGKILL 后释放与归零、大/小窗口及 resize、正常画面恢复、关闭和堵塞输出。

历史验收结果、独立审查及修复证据见 [计时器审查记录](../reviews/timer-review-2026-10-14.md)。
