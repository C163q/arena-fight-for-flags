# 参赛题包改进准备清单

状态：待讨论与实施，2026-10-16。本文件整理实测发现、建议范围和验收标准，不改变当前规则、接口、赛程或题包白名单。证据见 [参赛体验](../reports/contest-kit-selftrial-2026-10-16.md)；三份提交的统一对抗见 [评测报告](../reports/submissions-2026-10-16.md)。

## 建议顺序

| 优先级 | 候选改进 | 当前问题 | 建议验收 |
| --- | --- | --- | --- |
| P0 | 独立运行环境与 AI 接口预检 | `EPERM` 加载失败仍可产生完整比赛；需要翻调用明细定位 | 用很短的真实 worker 调用检查 ABI/加载/通信/信号权限，给出阶段和原因；与正常比赛故障统计分开 |
| P0 | 默认小规模自测入口 | 完整示例的规模大，虽有警示仍容易误启动 | 默认不超过两场，开始前显示地图、换位范围、并发和预计规模；扩展测试显式指定 |
| P1 | 固定种子清单的版本对照 | 不同版本各生成随机计划，容易把种子差异当作策略收益 | 显式共享引擎种子与出生位，AI 种子流仍独立；每版分别冻结输入和保存哈希，不覆写旧计划 |
| P1 | 公开战斗/夺旗指标摘要 | 每位选手重复编写逐轮 JSON 分析器 | 汇总拾旗、交旗、携旗阵亡、有效射击、动作执行结果；可追溯到原始事件，说明分母与统计定义 |
| P1 | 回放归档与磁盘估算 | 完整状态与事件重复存储，数百场占用数 GiB | 先按小样本估算磁盘；提供压缩归档和检验步骤，保留权威记录，避免默认删除或影响续跑 |
| P1 | 丰富自测对手的简短指导 | 对基准更好不一定能赢其他策略 | 建议保存风格不同的自写历史版本互战；不分发良好策略源码，不把基准胜率写成最终成绩 |
| P2 | 地图竞技区分能力复核 | 最近旗点等距，但部分出生位得分差较大 | 用多策略、多种子完整轮换比较每槽得分、胜率、运输与战斗；区分位置、策略和交互影响 |

## 实现前须确定的边界

### 预检

预检是诊断工具，不能把所有非零 AI 返回、崩溃或超时改判为基础设施错误。正常评测仍按现行规则计入故障；只有裁判、冻结输入或记录校验问题才中止测评。不能仅凭 `EPERM` 自动要求扩大权限，也不能声称 worker 已提供恶意代码的完整沙箱。

建议把环境可用性和参赛库接入分成可识别的阶段，帮助场外人员判断如何配置运行环境；具体命令、诊断输出和平台支持范围留待实施设计。接口布局自检可使用二进制内置局面，不需要公开策略示例。

### 小规模自测与共同种子

现有 `tournament.py --only 2p --mode quick --repeats 1` 已能执行两场，现有 league 已能自动组合与补位；候选改进是减少入口误用和版本对照的手工步骤，不重新实现赛程器。

“共享种子”表示控制实验的输入条件，不代表两种策略会经历相同的未来世界。每种新库须生成独立冻结计划；不得更换旧计划中的库来复用成绩。跨场并发默认及正式评测仍为 1；并行自测保留既有来源标记。

### 指标与记录

先明确统计定义，再设计输出。射击未命中、障碍遮挡、移动争格、因射击先死亡、游戏规则非法和 ABI 故障需要区分；不能把移动未成功全部算作非法操作。同轮掉旗导致携旗移动失效属于已知规则边界，应保留可定位事件。

摘要只能来自原始公开记录；不新增未来刷新或 RNG 信息。归档后仍应能恢复原始文件并通过裁判验证，进行中的比赛与可续跑计划不能被自动清理。实际是否压缩、压缩格式和导入方式留待设计。

### 题包披露与版本

保持 release 二进制、纯 C 头文件、完整接口文档及独立参赛模板；不把维护者报告、改进清单、自测策略源码或硬件容量探针复制给参赛者。现有 ABI 公开参数如实说明；题面未展开机制仍可通过允许的实验探索。

修改工具后同步模板、显式白名单、包内链接和维护者指南，再生成新题包并做仓库外验收。旧分发目录与冻结赛程保留其原版本；不能把升级后的地图或预算静默套到旧记录上。

### 地图与规则

本次没有批准新的玩法规则或地图数值。地图复核首先形成证据，再讨论具体调整；不预设必须完全公平，也不把出生位差异直接归因于障碍或旗点布局。若修改地图，继续遵循封边、可达性、距离检查与正式基准标定要求。

## 本轮准备工作的完成标准

- 保存当前三份提交的来源、哈希、原题包提交及当前裁判/地图指纹。
- 在既有 league 中串行完成精确均衡的重复块，保留原始回放及完整块排名；不修改参赛 AI。
- 把体验、对抗结果、候选改进分开记录，明确样本和版本限制。
- 更新文档导航及指南引用；本轮仅整理文档和执行测评，功能实现另行开展。
