# 计时查询的 PID 命名空间兼容修复

用户在已定位根因后要求正式修复。此前独立临时锁复现：沙箱与宿主共享 inode，`F_GETLK` 均成功且返回锁存在，但宿主获得实际持有者 PID，沙箱获得 0。Linux PID 命名空间还可能把同一进程映射成不同的正数 PID。

## 修复

保留固定 `/tmp/fff-session-timer-v1`、`FFF_TIMER_V1 pid start_ns` 格式和全部命令约束。记录中的正数 PID 只作诊断，不再要求与 `F_GETLK.l_pid` 相等；锁存在与否必须使用 `l_type` 判断，0 也可表示不可见的活锁持有者。

查询继续只读打开，检查普通文件/单链接。在每次单例锁查询的同一个内核快照中检查完整持锁区间：初始化为 `[0,2)`，发布后才是 `[0,1)`；只有后者可继续。再前后检查持有者、初始化锁、两次完整有界内容读取与合法格式。不同持有者或内容变化仍重试；无锁即未运行，初始化锁存在即未就绪。起点在持有初始化锁期间写入，完成后才释放该锁，稳定发布状态与锁共同承担会话校验，不用命名空间相对 PID 作身份凭据。

相比只放行 `l_pid==0`，移除跨来源 PID 相等假设也覆盖正数重映射；相比改状态协议/添加控制服务，这不要求人类重启既有计时器，旧计时器可配新查询器。查询不加锁、不解锁、不写状态、不发信号，不引入路径覆盖或任何计时控制入口。

仍要求内外共享同一状态 inode 和同一 `CLOCK_BOOTTIME` 时间基准。独立 `/tmp` 或时间命名空间不由本修复打通；同 UID 任意篡改不是现有安全承诺。

## 验证与交付

先证明旧实现拒绝“锁持有者 PID 与稳定记录 PID 属于不同命名空间”的状态。真实子命名空间检查不可见持有者的 `l_pid==0`，新查询成功；环境禁止创建命名空间时明确标注缺失，不冒充成功，并补宿主/实际工具沙箱边界验证。保留未发布、残留、重启、只读和特殊文件用例，执行完整计时器验收，测试仅控制自己启动的实例，已有人工实例存在则不启动新实例。

使用当前会话已约定的实施与一次独立审查流程，同步使用说明和参赛材料，生成新 release 题包、仓库外验收，本地提交和合并；不修改外部参赛目录，不覆盖旧题包。

独立审查发现并修复的竞态：两个未发布实例交替退出，使分别采样的单例锁和初始化锁均看似就绪，且两次 PID 都为 0。完整锁区间的原子判断阻止这一组合；确定性回归使用真实内核锁与真实 PID 命名空间，不伪造 syscall 返回值。
