# 测评机并行自测设计

用户要求为参赛者提供可指定并发数、默认 1 的评测选项，解释代价，并明确正式评测使用 1。

采用 `run ROOT --jobs N`：线程池只编排独立裁判进程，最多 N 场在途（包含回放校验），单场内队伍仍串行决策。相比多进程编排，线程池可共享取消信号和输出锁；相比拆分多个计划，不破坏原计划的种子、换位块和续跑约定。只接受正整数，默认 1；不自动按 CPU 数提高并发。

主线程独占调度、检查点和进度输出。每场有独立 attempt、日志和状态；提交前校验冻结输入，完成后验证回放和输入。只保持至多 N 个任务；`--max-matches` 限制本次启动的新比赛总数。失败或中断停止补充任务，通知所有在途命令终止并等待回收，保留完整场和半场。原 Linux 父进程死亡保护、继承输出锁继续覆盖所有 runner/verify 子进程；SIGKILL 后不得提前解锁而留下活跃裁判。

每个 attempt 保存本次 `jobs`，验证后带入结果。旧 attempt 无字段时按既有串行实现认定为 1；非法新字段拒绝。报告 JSON/CSV/Markdown 给出已采用场次的并发设置，只要其中有 `jobs>1` 就标记为并行自测（混合续跑亦然）。完整换位块仍可生成供自测的排名，但不冒充串行正式成绩；正式赛创建独立计划并使用 `--jobs 1`。此字段记录配置并发上限，不保证实际同时有 N 场，不提供防篡改认证。

并行争抢 CPU、内存和磁盘，墙钟预算仍为首回合 250ms/后续 50ms，因此可能增加超时、改变行为和排名，不承诺线性加速或无超时。独立单场和 `jobs=1` 也会受外部系统负载影响。

更新仓库及题包两层说明：balanced 的 2–8 人一块 198 场、五块 990 场；quick 一块 35 场，单选 2p 一块 2 场。建议先单场/2p quick、有限分段，再扩大测试；LLM 60 分钟包括自测，应查询计时器并保留可提交库。明确磁盘与并发资源成本，不在本次增加自动时限、CPU 绑核或更改赛制。

验证包含实际进程重叠与并发上限、分段/续跑、混合报告、异常取消和 SIGINT/SIGKILL 多子进程清理，以及正式 release 对战和仓库外题包验收。
