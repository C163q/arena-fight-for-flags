# 多 AI、多地图测评设计

状态：2026-10-16 用户确认同场对抗、优先精确两两均衡、通常不超过 16 个 AI，以及本设计的排名口径；开始实现。

## 输入与兼容

新增 `scripts/league.py`，复用现有 tournament 的真实 runner 执行、输入冻结、锁、恢复和并发来源。旧版固定名单工具和配置继续使用。Python 3.10+ 标准库；不新增运行依赖，不改游戏规则与 C ABI。

JSON 配置 version=2，包含 runner、非空 participants（id/name/library）、非空 maps（id/map）、可选 filler（name/library）、repeats（默认 1）。路径相对配置文件。参与者 ID 唯一；同库可对应不同参与者。地图人数通过新增 `fff-runner inspect-map PATH` 读取并完整校验，不由 Python 猜测 RON。填充仅在候选数小于地图容量时需要，每场每个候选最多一队；填充队伍独立编号、种子，不进入排行榜。

命令为 `plan --config ... --out ... [--repeats N] [--only MAP_IDS...]`、`run ROOT [--jobs N] [--max-matches N]` 和 `report ROOT`。plan 不调用 AI；显示全部场数及均衡验证，run 才执行。默认与正式 jobs=1；并行自测标记、混合续跑、原始回放验证规则不变。

## 精确均衡赛程

一个地图重复块包含该地图全部候选的完整赛程。块内候选出场次数、单队出生位次数、任意候选对的同场次数和所有不同有序出生位对次数必须精确相同且非零（单候选无候选对）。生成后独立遍历实际场次重新计数；不相信构造名称或缓存。

候选数不超过容量时，补足独立填充副本，复用已有 balanced 位置置换。超额时优先使用有限域上的仿射置换并截取容量个位置，联合解决组队与换位。例如 16 个候选、8 人图为 240 场，每队 120 场、每位置 15 场、每候选对 56 场、每有序位置对 1 场。

非素数幂人数优先采用可验证的紧凑组合构造：6 阶既有射影置换、10/12/14 阶有限射影线置换、15 阶几何或循环组合模板，组合模板再应用 balanced 出生位置换。最后保留完整子集组合加 balanced 换位作为通用兜底。不承诺最少场次、三方以上组合均衡或地图公平。支持更大名单但不保证紧凑；计划默认限制 10000 场，`--match-limit` 可显式提高，只限制规模，绝不截断均衡块或降级近似均衡。

每块独立随机重标记候选和出生位、打乱场次。块内引擎 seed 固定，AI seed 跟随独立队伍身份；引擎、AI、赛程种子独立来自 OS。完整实际赛程、输入指纹与环境写入计划 version=2，旧 version=1 仍可加载。

## 统计

每地图只采用完整、真实验证通过的块。候选的归一化名次分仍与场内全部对手（含填充）比较；填充队不入排名。记录平均游戏得分、独胜/并列第一、出生位成绩、两两混战胜平负及实际同场样本数、调用耗时/超时/非法动作。不同候选组合不拆成互相不可比较的独立排行榜。

总体成绩为各指定地图名次分的等权平均；仅采用同一重复序号的所有指定地图均完整的重复组。缺地图或缺块时明确列出不完整状态，不用完成较快的地图替代全图比较。总榜同主分保留并列，不跨地图用原始游戏分破同分。每地图沿用主分、平均游戏分、独胜率破同分。至少五个完整重复块/全图重复组才按该单位配对 bootstrap（2000 次、固定统计种子）给描述性区间。

输出 report.md、standings.csv、results.json，保留所有已验证逐场结果；无完整块无正式名次。完整全图组和每地图完整块的样本量分别列出。执行并发标记取所有已采用场次，不能被总榜过滤或续跑清除。

## 验证与范围

测试所有 1–16 候选和 2–8 容量的实际计数；验证非法配置、计划规模限制、缺填充、map inspector 拒绝非法地图、候选缺席统计、重复块完整性、跨地图等权、缺地图组过滤、同分、填充排除、旧计划兼容与并行标记。

真实 release runner 短局验收覆盖不足/等于/超额人数、多地图、分段与续跑、损坏回放拒绝；同时执行已有 tournament 真实验收和父进程清理。短局仅修改测试私有地图，正式 RON 不改。题包工具继续发放旧版固定名单自测器；新的场外 league 编排暂不加入参赛题包，不泄露组合模板或维护者实测材料。最后独立审查、修复、记录证据并本地提交，不推送。
