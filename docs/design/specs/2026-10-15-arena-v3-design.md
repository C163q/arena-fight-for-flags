# 首回合预算与地图 v3

用户已确认本方案并授权实施。目标是支持首回合预计算，增加夺旗运输和竞争距离；不修改既有外部测评或参赛目录。

## 计时

正式比赛第 1 回合整队决策预算 250000µs，第 2 回合起 50000µs；仍包含恢复、通信和完整响应校验，排队不计时。仅按比赛回合号判断，故障重启不重新获得首回合优惠。初始化 1000ms、退出 100ms、串行和超时整队等待机制保持现有约定。

C ABI v1 布局不变。`CtfInit.decision_budget_us` 继续表示常规回合预算 50000；首回合例外在头文件和接口文档中明确说明，以观测的 `turn == 1` 判断，不能使用进程的 `first_turn` 判断。回放 manifest 的时间策略文字记录两档预算；旧回放仍可读取和验证。

## 地图

保留 2–8 队地图尺寸、出生区、20 分目标和旗点数量，将外围旗点向中心收拢。出生区九格到最近旗点的最短路径以 6–8 步为目标，最近距离槽间差不超过 1 步；所有旗点唯一、出生区合法、外圈封墙、地面连通。稀疏障碍由原生成器重建，不能人为加绕路来达到距离要求。

只收拢旗点优于整体放大地图（控制比赛成本），也优于大量加墙（避免新增狭口和位置差距）。几何等距不等同于胜率相等，继续依靠轮换评测。不能保证距离增加一定扩大所有算法之间的优势。

使用正式 release 基准自战，每图五个种子，试跑上限 3000；仅用达到目标分的完整记录标定，保留约 35% 余量、向上取百，人数增加上限至少增 100。默认上限另用两个独立种子验证。截尾或故障不得混入标定。保存新概览和报告，旧地图报告明确标注历史版本。

## 交付与验收

计时使用真实 C 动态库验证 100ms 首回合成功、普通回合失败、超时后恢复、重启不放宽及首回合超限。地图检查几何约束、真实加载和自战。同步项目与参赛文档、决策、AGENTS 和回放时间策略；使用新目录生成 release 题包并在仓库外验收。参考已完成的外部 990 场报告与现成 AI 作为背景，避免为特定 AI 的输赢调图。最终一次独立审查、本地提交，不推送。
