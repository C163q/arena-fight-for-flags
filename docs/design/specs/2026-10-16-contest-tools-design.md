# 参赛开发工具改进设计

状态：已实现并完成实战、仓库外题包验收及独立审查修复（2026-10-17）；一项Markdown显示Minor保留，见审查报告。用户要求继续完成 [改进清单](../contest-kit-improvements.md)，已确认版本对照采用“分别面对固定对手”，选手之间的同场对抗继续使用 league。

## 目标与边界

让参赛者在有限开发时间内快速发现环境/接口问题、运行小规模测试、可靠比较版本，并从既有回放获得可读指标、保存记录。默认不启动大赛程、不改变玩法或 AI 预算，不提供优秀策略源码；计时器仍由人类控制。

推荐新增统一 Python 入口 `scripts/selftest.py`，复用当前 Rust 裁判、worker、固定名单赛程器与执行器。相比把所有功能加入 Rust runner，避免改变比赛程序的职责；相比多个互不相干脚本，便于发现命令、统一输出和题包维护。新功能加入显式题包白名单；league 仍只用于场外。

## 命令与默认值

所有命令在解压题包根目录可用；也可在仓库使用显式 `--runner`、`--opponent` 和地图路径。路径参数按调用工作目录解析，不执行 shell 拼接。

| 命令 | 作用与默认行为 |
| --- | --- |
| `selftest.py check --ai submission/libteam.so --out runs/check-new` | 先检查当前基准库在真实 worker 中是否可运行，再检查参赛库；使用私有两回合测试地图，输出分阶段诊断及日志 |
| `selftest.py run --ai submission/libteam.so --out runs/selftest-new` | 默认 2 人原图、quick、一个重复块、jobs=1，仅两场完整对局，先打印总场数与配置 |
| `selftest.py compare --ai old=old.so --ai new=new.so --out runs/compare-new` | 至少两个版本，分别对固定对手测试；共用地图、种子和位置安排，每版使用独立冻结计划 |
| `selftest.py resume runs/compare-new` | 使用已冻结的输入续跑；不读取替换后的提交库，不把不同版本混入旧计划 |
| `selftest.py summary MATCH_OR_SELFTEST --out analysis-new` | 验证并分析已有记录，生成简短 JSON 和 Markdown、磁盘用量与样本估算，不运行 AI |
| `selftest.py archive MATCH_OR_SELFTEST --out replay-new.tar.gz` | 对已完成单场或已完成自测实验制作带清单与哈希的 gzip tar 归档，不删除原文件 |
| `selftest.py restore replay-new.tar.gz --out restored-new` | 校验并恢复到不存在的新目录；验证所有比赛记录，失败不发布半成品 |

run/compare 允许重复 `--map`、指定 `--opponent`、`--mode quick|balanced`、`--repeats`、`--jobs`、`--seed-file`。默认对手为题包基准，各空余席位是同一对手程序的独立队伍。run 仅接受一个候选；compare 的版本名唯一且使用现有 ID 约束。候选和地图数量扩大必须显式指定。地图 ID 取正式 inspect-map 返回值，并遵循现有赛程 ID 约束；不合法或同 ID 内容不同时报错，不静默改名。

所有新输出路径必须不存在，不覆盖旧结果。run/compare 的新计划准备在私有暂存目录中完成后发布；执行期间保持输出锁，支持 SIGINT/SIGTERM 保留现场。复用现有 runner/worker 清理链，额外测试包装入口的 SIGKILL 和锁生命周期。compare 各版本依次执行，整套实验最多 jobs 场并发，不把版本数乘到并发数上。混合续跑继续保留并行来源标记；正式评测始终 jobs=1。

## 环境与 ABI 预检

不在 Python/裁判进程中 dlopen 参赛库。先用附带基准做控制调用，检查 runner/worker、地图、IPC、初始化和调用；控制通过后才检查候选。诊断报告区分文件/ELF或加载问题、ABI/符号/响应问题、崩溃、初始化失败和调用超时，保留原始错误文字。

预检的两回合地图由正式地图经正式 inspect-map 校验后生成私有副本，仅缩短回合上限；不修改原图，不将预检得分当成强度成绩。成功只证明本次输入上的接入，不保证其他局面必不超时。

基准控制也出现 EPERM 时提示运行权限或隔离配置可能不支持所需操作，交由场外人员处理；不自动扩大权限。候选失败与环境控制失败分别标记。预检不改变正常比赛中 AI 故障计入成绩的规则；游戏规则非法操作单独列出，不混同 ABI 失败。check 返回 0 表示通过，1 表示环境/候选检查失败，2 表示命令或输入无效。

## 共同种子版本对照

用户已确认：A/B 不必直接互战，而是分别对同一对手、相同出生位与随机条件运行。每个版本的库、对手、地图独立复制冻结，报告记录哈希；最终比较每地图千分制积分、平均夺旗分、故障和动作指标。对照结果不能当作正式 league 名次。

每次新自测自动生成可复用 `seeds.json`；`--seed-file` 可复用该文件，也可显式提供引擎种子列表。格式为版本化 JSON，含：

- `version=1`。
- `ai_seed_root` 与 `schedule_seed_root`：两个独立 OS 随机的 256 位非负整数，分别控制 AI 种子和换位安排。
- `maps`：按稳定地图 ID 索引，每项含原图 SHA-256、人数，以及每个重复块的 `engine_seeds`（无符号 64 位整数列表）。

所有选定地图必须存在对应条目，人数、哈希和重复块数匹配；拒绝 bool 冒充整数、越界、重复引擎种子和不完整列表，失败不发布输出。引擎种子不派生 AI 种子。不同版本使用相同逻辑角色 ID（candidate/opponent_1…），保证候选及对手的 AI 种子随角色换位。固定名单工具的计划创建增加可选种子输入，默认路径保持现有独立 OS 随机行为，兼容旧计划。

同一组种子不意味着策略不同后仍经历相同未来刷新轨迹；它控制的是可固定的输入条件。比较强度仍需多个种子与完整换位。提供保存旧版本、换用不同自写对手的简短指导，不新增良好策略源码示例。

## 回放摘要与磁盘估算

摘要先通过正式 runner verify，随后流式读取逐轮 JSON；不信任缓存统计，不把格式检查等同于规则验证。单场要求 complete，实验只使用已完成且验证有效的场次，未完整重复块的动作指标可展示但不生成正式排名。

按队伍/候选汇总：调用状态与延迟、提交的移动/射击/等待数、合法射击的命中/未命中/遮挡、名义命中伤害、实际承受扣血、死亡、携旗死亡、拾取/生成即携旗、交回得分，以及移动成功/争格/占格或环/射击先死取消/非法。每项定义分子、分母；各比率不能混用。

名义命中伤害包含同时射击的过量伤害，不能冒称实际扣血或独占击杀。死亡按受害者统计，携旗死亡根据回合开始状态/掉旗事件关联；不按事件遍历顺序给最后射手独占击杀。移动 blocked/cancelled 不算非法；同轮掉旗造成的非法移动保留规则原因。提供有界的代表性事件引用（比赛、回合、event_id），完整数据仍在原始记录。

汇总只输出公开行为指标，不输出 RNG、未来刷新时间或引擎私有状态。统计失败给出文件/回合定位，不能把坏记录当成零值。输入和资源校验复用或遵循现有回放约束：单 JSON 16MiB、单场 JSON 总量 512MiB、最多 25000 帧。

磁盘估算报告当前字节数、每场/每轮样本均值，以及按同地图已测样本推算的计划数据量；可指定要估算的场数。样本不足明确标记，跨地图或跨算法估算只能作为粗估，不承诺上界或压缩率。

## 非破坏归档与恢复

归档支持完整比赛目录或本工具已完成的实验目录。实验归档时获取其锁和内层计划锁，拒绝在途任务或未完成计划；不能清理进行中的比赛或续跑数据。单场归档以 complete 状态和正式验证为前提。

归档有独立 `fff-replay-archive` v1 清单，记录相对路径、字节数、SHA-256、比赛目录和格式；复制必要的原始比赛与实验元数据，排除锁、临时文件、缓存和无关源码。仅接纳普通文件，拒绝符号链接、硬链接、设备、FIFO、套接字、路径越界和归档自包含。制作前后检查源文件元数据与内容一致性，冲突时失败，不发布输出；不会删除源文件。

恢复不调用不受控 extractall：逐条校验相对路径、重复项、文件类型、清单一致性、尺寸和哈希，使用私有目录写入。默认最多 1000000 文件、未压缩总量 64GiB，可通过显式正整数参数调整；清单本身有限制。恢复后逐场通过正式 runner verify，再原子发布到新目录；失败只清理本次暂存目录。

恢复用于离线验证/查看和备份，不承诺测评目录迁移后可以继续运行：现有计划保留 runner/worker 和输入绝对来源指纹。原实验仍原地保留，续跑使用原目录；不改写历史 provenance 或指纹以绕开校验。

## 组织与交付

预计新增 `scripts/selftest.py` 和职责分离的 `scripts/contest_lib/` 模块（预检/实验、摘要、归档）；固定种子支持放在现有 tournament 存储层的独立小模块中。模块通过明确输入输出协作，不把单个入口堆成大文件。

同步维护者指南、独立参赛模板、显式包文件名单与文件数测试；release 二进制、C 头文件及 60/70 分钟时限保持不变。不把内部设计、报告、CPU 探针、源码策略或 league 加入参赛包。

验证包括种子复用和冻结输入、默认恰两场、预检的正常/坏 ABI/崩溃/超时/权限失败、摘要边界和坏记录、归档/恢复及路径攻击、全部在途任务中断和父进程死亡清理、旧工具兼容、仓库外题包接入。少量真实对局验证工具，不在 Codex 中重跑正式 1010 场；长评测命令交由用户在宿主运行。

地图部分先形成多策略、多种子、按出生位的证据报告；本轮不直接修改地图或数值。若证据支持布局调整，另提出具体方案并按既有地图标定流程确认。
