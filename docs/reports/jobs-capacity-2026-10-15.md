# 本机并发容量实测

结论：本机 **16 个可用逻辑 CPU 推荐自测并发 8**（核数一半），本轮所测档位连续通过的最高并发为 **10**。12 已出现额外超时，16 明显干扰。**默认及正式评测仍为 jobs=1**。这不是对其他机器或真实 AI 的安全保证。

## 环境与方法

Intel Core Ultra X7 358H，16 个逻辑 CPU 均可用，约 32GB 内存。lscpu 显示16个不同core_id：4个频率上限4.7–4.8GHz、8个3.7GHz、4个3.3GHz；没有把它们视为同等算力。可读父 cgroup CPU 配额均为 max。完整拓扑和频率附件位于原始目录的 hardware-topology.txt。
测前负载（1/5/15分钟）：[0.87109375, 1.474609375, 2.05859375]；测后：[2.4482421875, 3.38330078125, 2.97705078125]。当前 Python 3.14.8，平台 `Linux-6.18.55-1-lts-x86_64-with-glibc2.44`。

正式 release runner/worker，八人地图仅复制并将上限设为24轮，正式地图未改。每组两个quick块共16场；1/2/4/6/8/10/12/16并发先升序、再倒序，各用基准八队和35ms线程CPU探针。共32组、512场、98,304次决策；每场由正式verify验证。
探针通过公开C ABI忙循环消耗约35ms线程CPU时间后提交等待，检测调度挤占；不是睡眠，也不访问引擎私有数据。CPU时间不包含未被调度的墙钟等待。它不模拟真实算法固定指令量在异构核上的变慢、复杂缓存行为或长时间热稳态。探针源码仅为内部测试夹具，不进入参赛题包。

预先门槛：两个方向均无AI故障/非法动作；探针常规回合P95不超过同方向串行的110%、P99不超过120%；只取所测档位从低到高连续通过的最高值。首回合250ms与常规50ms分开统计，门槛只比较turn>1；故障统计仍覆盖全部回合。少量样本零超时不证明未来零超时。

```sh

```

内部脚本需要C编译器和允许worker进程操作的Linux环境。每组固定16场，因此只接受1–16并发，并必须包含1；不允许把请求32却实际最多16误报成容量32。独立方法审查发现该边界后，两个回归先RED再GREEN，CLI在创建输出前拒绝超界，聚合也拒绝；当前默认矩阵1–16不受该修复影响，无需重跑。Python45项与播放器8项通过。
一次方法审查另记录自动机器快照只包含cpuinfo首段的限制：本次以外部完整lscpu附件补全，不宣称脚本已自动采集完整拓扑。审查及处理见[容量审查](../reviews/jobs-capacity-review-2026-10-15.md)。

参赛者在本机有明显计算余量时可从8并发自测，接近50ms预算、存在其他负载或在其他机器上时降低并发并先测少量局；未知环境从2开始。需考虑有效CPU配额/亲和性、异构核、内存、磁盘、策略自身计算量和长赛程热状态。最终在低负载jobs=1复核。
