# 系统架构 v1

首版已实现。不同队伍串行调用，补充默认方案已接受，见 [设计决策](decisions.md)。具体类型与函数以代码和公开头文件为准。

## 边界与三种可行路径

采用 **C ABI 动态库 + 每队独立 worker**。动态库满足 AI 是库、暴露 `extern "C"` 的要求；worker 让裁判能终止超时或崩溃的 AI。第一版面向 Linux，本地运行由参与者信任的 AI。

另两种路径：裁判直接加载库的实现量最小，但 AI 的死循环、崩溃和内存写坏会影响整场比赛；WASM 运行时有利于资源约束与移植，但需要额外设计运行时、计量方式及 C ABI 桥接。首版推荐 worker，恶意代码沙箱作为未来独立工作。

```text
AI 作者 ──编译──> team_a.so ──加载──> worker A ─┐
                                             │ 请求 / 响应
AI 作者 ──编译──> team_b.so ──加载──> worker B ─┤
                                             v
                                      runner（裁判 / CLI）
                                             │
                           ┌─────────────────┴──────────────┐
                           v                                v
                     engine（纯规则）                 replay（记录）
                                                            │
                                             ASCII 给 LLM / JSON 帧
                                                            │
                                              viewer 导出器 -> HTML
```

图中展示两个 worker；多队比赛为每支队伍创建独立 worker，扩展到最多八个。队伍数量与队伍 ID 是运行时数据。

## 实际模块

Cargo workspace 与独立 Python 导出器：

| 路径 | 责任 | 依赖边界 |
| --- | --- | --- |
| `crates/engine/` | 地图、状态、动作校验、纯回合结算、确定性随机 | 不依赖 FFI、worker、UI 或实际时钟 |
| `crates/ai-abi/` | C 兼容数据结构、版本、常量；未来 C 头文件来源 | 不依赖引擎内部实现 |
| `crates/ai-sdk/` | 公开 BFS/参考策略工具，只依赖 ai-abi | 不依赖引擎私有状态 |
| `crates/ai-worker/` | 加载指定库、ABI 检查、生命周期调用、进程通信 | 使用 `ai-abi`；不包含对战规则 |
| `crates/runner/` | CLI、比赛配置、worker 监督、预算、状态到观测的转换 | 调用 engine、worker 协议与 replay |
| `crates/replay/` | 结构化记录、ASCII 渲染、读取与验证 | 依赖已版本化状态格式 |
| `bots/baseline/` | 中等强度 AI 动态库 | 只依赖公开 AI 接口 |
| `bots/wait/`、`bots/greedy/`、`bots/test-fixture/` | 等待、追旗与故障注入参考库 | 使用同一公开接口 |
| `viewer/` | Python 导出器与原生 HTML/JS 播放模板 | 只消费回放格式，不依赖 AI 库 |
| `maps/` | 固定地图、合法性检查输入 | 数据资产 |
| `docs/` | 本仓库设计、规则、接口与使用说明 | 文档 |

## 一回合的数据流

1. 引擎处理到期复活，产生只读的回合开始状态；定时旗帜生成尚未执行。
2. runner 从同一状态构建各队观测。全图及所有棋子的坐标、血量、携旗状态已确认公开；其他可见字段按规则契约提供，不包含其他 AI 本回合动作。
3. runner 依次向每队 worker 发送一次带比赛、队伍、回合编号的请求；同一时刻只允许一队执行决策，worker 调用一次 AI 函数产出三个动作。按稳定队伍 ID 顺序调用并记录实际顺序。
4. runner 根据完整响应的到达时间和格式决定该队提交是否有效。收齐 2–8 支队伍的结果后才让引擎结算。
5. 引擎使用统一快照结算射击、伤害与死亡掉旗；再检查移动合法性并统一移动。按已确认阶段先处理已有地上旗拾取，再处理到期生成：空格生成、未携旗占格生成并立即携旗、已携旗占格失败重新随机等待；最后得分及终局判断。
6. recorder 保存实际输入、降级原因、射击者/目标坐标/射击结果、伤害来源、血量和携旗变化以及完整状态；从这份结构化数据生成 ASCII 与文字事件明细。

阶段定义以 [规则](rules.md) 为准。AI 的调用先后不得改变其收到的状态。

## 超时和失败

已确认各队 AI 串行调用；每队始终看到同一局面，排队等待其他队伍的时间不计入本队 50ms。裁判使用单调时钟维护每队独立截止时间：从派发该队请求前开始，到收齐并验证整条响应。不要接受截止后才收到的结果，也不要将部分输出应用到局面。8 队均用满预算时，决策窗口总和为 400ms；总回合时间还包括切换、故障清理、初始化、结算与记录。

只依次调用函数不足以消除仍在后台工作的其他 AI 的负载。worker 在决策窗口外暂停其进程组，确保上一队已经暂停或终止并回收后才开启下一队窗口；Linux 使用 SIGSTOP/SIGCONT 并确认暂停，故障终止整个进程组。加载、初始化和故障重启也串行安排，不与其他队伍的决策窗口重叠。AI 不得将后台计算延续到调用结束之后；这些机制不等于恶意代码沙箱，也不能消除系统中其他程序的负载影响。

超时、worker 崩溃、畸形响应或 AI 显式返回失败时，整队本回合等待。终止对应进程组，关闭管道并回收子进程；下一回合重新创建 worker 并初始化，内存中的策略记忆不保留。正常响应中的单个非法游戏动作只让对应棋子等待。区分“协议失败”和“动作不合法”。

初始化和重启不占用回合 50ms，但仍必须有有限预算。初始化/重启 1000ms，退出 100ms；长期无法加载的队伍每轮等待，不无限阻塞比赛。输出日志走独立的有界通道，不能与协议 stdout 混用或塞满管道阻塞裁判。

runner 与 worker 使用继承 Unix socket、四字节小端长度前缀及最大 262144 字节的显式 JSON 消息，不发送裸指针或 ABI 内存镜像。每条消息包含协议版本、队伍、回合、请求 ID，裁判拒绝迟到或串轮响应。内存预算与进程组清理由平台适配层实施；限额设定失败应报告并停止启动，不能假装已隔离。

这一结构不能阻止本地库自行访问磁盘、网络或创建子进程，完整安全执行需要操作系统沙箱。不要把超时隔离当成安全执行任意不可信二进制的承诺。

## 随机与可复现性

引擎在地图、初始出生、复活格选择和旗帜刷新中使用明确指定的伪随机算法。记录算法版本、种子及确定的抽样顺序；候选格和对象按稳定 ID/坐标排序。地图固定时，相同初始配置与已采用动作序列应产生相同状态和事件序列。

旗点维护其当前关联旗 ID 或交回消失后的刷新调度，不能用“旗点地面上是否有旗”判断是否空闲。拾取和死亡掉落保留原关联，旗帜没有自动过期；交回得分消失时才为来源旗点抽取下一次延迟。重刷延迟默认在闭区间 5–15 回合内均匀抽取整数，上下限是本场可调配置，开局后不改变，并记录实际参数与结果。

首次生成政策已确认：t=0 从 N 个旗点随机无放回选择 `max(1,(N+1)/3)` 个立即生成，使用整数除法，其余分别安排首次延迟，当前 5–15 回合。初始记录同时包含立即生成的旗与尚未到期的调度。

所有正式回合的生成尝试位于移动之后。已携旗者占据旗点时不创建旗帜，重新抽取 d 并将下一尝试设为当前回合 t+d；未携旗者占据时生成并立即携旗。失败重试保留同一待生成任务的来源关系，不能伪造旗帜消失，也不能因为不存在已消失的上一面旗而漏掉首次生成失败后的重试。

AI 有自己的种子，不直接共享引擎随机流。AI 计时、调度和故障不保证可复现，所以回放以实际采用动作及故障记录为准。验证器重新执行规则引擎，不重新运行参赛 AI。

## 地图与配置验证

支持 2–8 名参赛者，按每人一队、每队三个棋子设计。使用运行时读取的 RON 地图资产，七张候选地图及 schema 见 [地图设计](maps.md)。当前尺寸为 25×25 至 41×41，并非按人数在同一张地图上随意取前几个出生区。

加载时验证矩形尺寸、四边全为障碍、人数与出生区数量匹配、出生区大小与不相交、旗点唯一且位于可行走非出生格、所有出生区到所有旗点可达。地图错误直接报告并拒绝开始比赛，不自动补墙或移动出生区。棋子占格与物品占格分开：一格最多一棋子，可以有旗帜。

规则常量、本场参数、原始 RON 及解析后的地图完整保存到回放目录。最大血量 3、每发命中伤害 1、无自然回血、曼哈顿射程 5、只伤害指定格、途中棋子不挡弹、友伤开启及自射禁止是已确认的固定规则，不能通过比赛配置覆盖。首版只允许文档明确列出的其他可配置参数，不通过隐藏开关改变移动或射击算法。

实际构建、比赛与验证命令见 [README](../README.md)。worker 关闭 core dump，避免崩溃转储处理延迟退出；内存限额为地址空间 256MiB。终局阈值直接读取地图 RON。

裁判强制退出时，worker 的 Linux 父进程死亡信号会终止 worker；真实 CLI 测试通过领养并回收孤儿进程验证，避免将 `/proc` 不可见误判为已经退出。正常结束/故障仍由 runner 对进程组清理。
