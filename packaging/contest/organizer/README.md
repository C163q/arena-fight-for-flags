# Fight for Flags：场外人员说明

这个文件夹交给裁判、组织者或运行编程 agent 的人员。参赛者可以是独立的人类程序员，也可以是 LLM；只向他们分发 `participant.tar.gz`。

## 文件与准备

- `fff-timer`：由场外人员手动启动的总用时计时器，禁止 LLM 操作。
- `participant.tar.gz`：参赛所需的裁判、基准 AI、接口、地图、说明和自测工具。内含只读 `fff-timer-query`。
- 需要 Linux x86_64 GNU/glibc、libgcc_s，辅助工具需要 Python 3.10+。参赛者自行准备 Rust、C 或其他可生成 C ABI 动态库的工具链。内层 `manifest.json` 记录该构建需要的最低 glibc 版本；先在比赛机器确认工具能启动。

校验本次分发文件：

```sh
printf '%s  %s\n' '@ARCHIVE_SHA256@' participant.tar.gz | sha256sum -c -
printf '%s  %s\n' '@TIMER_SHA256@' fff-timer | sha256sum -c -
```

为每次参赛准备全新目录，将压缩包解压进去。只向 agent 暴露解压后的 `fff-contest/`，不要开放项目源码、外层目录或其他参赛者的文件；工作目录设为 `fff-contest/`。如果只改变工作目录却仍给 agent 全盘工具权限，并不能阻止它访问外层计时器。

## LLM 计时与收取

准备好环境和参赛指令，在 LLM 开始任务时，由人类在单独终端运行：

```sh
./fff-timer
```

保持这个进程运行。它从零开始；退出重启会重新归零，不存在暂停/继续。共享 `/tmp` 的环境只能有一个实例，因此使用这个计时器的 LLM 场次应依次进行；不同 `/tmp` 环境不能通过它共享起点。

LLM 的任务时限为 **60 分钟**，包括设计、编码、编译、自测。要求它时常运行 `bin/fff-timer-query` 查看总用时，在时限内准备好 `submission/libteam.so`。它不能操作 `fff-timer`、修改计时状态或重设计时。

达到 **70 分钟**时，场外人员必须强制终止 LLM 会话及仍在执行的编程任务，立即收取当时已经产生的编译结果，不等待补编译。**没有编译结果则视作弃权。** 已有结果按正常接口和运行要求验收。建议参赛者始终保留一份已编译的可提交版本，避免截止时只有源码或未完成构建。

计时器本身不会终止 agent 会话；场外人员应通过 agent 平台的控制能力执行截止。任务结束、收取结果后，由人类退出计时器。查询失败或计时器意外退出时由场外人员处理，不让 LLM 自行启动或重置。纯人类程序员不适用这项 LLM 专用时限，其时间安排另行约定。

## 正式比赛

收取 `submission/libteam.so` 及依赖说明，复制到场外裁判目录并记录 SHA-256。验证真实加载和回放，区分缺失产物、ABI 不兼容及正常 AI 超时/崩溃。

使用内层 `scripts/tournament.py` 和独立正式配置安排 2–8 队对抗。正式名单应替换自测配置中的候选与基准副本；每种人数恰好 N 个不同参赛 ID，可以按人数使用不同名单。

正式比较使用 `balanced`、多个完整重复块，保持比赛串行；排名只使用完成并验证的换位块。不要直接把某人对基准的自测结果当成所有参赛者的总排名。详见内层 `docs/testing.md`。

最终 AI 将与其他 LLM 或程序员的实现比拼，对手可能显著强于基准。将这一目标和参赛 README 一并传达，鼓励参赛者在时限内持续测试、分析与改进。

所有人使用同一份未修改的裁判、地图和评测规则。基准结果不保证最终名次。本地 worker 提供常规超时/崩溃隔离，执行不受信任的本地二进制需要场外人员自行准备合适的隔离环境。
