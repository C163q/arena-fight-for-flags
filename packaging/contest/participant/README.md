# Fight for Flags：参赛说明

你的任务是编写一个夺旗 AI，控制同一队的三个棋子，与其他参赛者争夺旗帜。每回合，比赛程序把当前局面交给你的 AI；你的 AI 返回三个棋子各自的操作，比赛程序负责执行并计算结果。

最终提交的是 `submission/libteam.so`。这是编译后的动态库文件：它本身不需要有启动比赛的入口，由比赛程序加载并调用。你可以使用 Rust、C/C++，或其他能够生成符合本题接口的动态库的语言，也可以完全不借助 AI 编程。

**你的 AI 最终会与其他 LLM 或程序员编写的 AI 比拼。他们的实现可能明显强于题包中的基准 AI。战胜基准只是一次自测结果，请继续分析失败、比较版本，并提交你能完成的最佳实现。**

## 从哪里开始

1. 阅读 [基本规则](docs/rules.md)，了解棋子如何行动、战斗和得分。
2. 阅读 [接口说明](docs/api.md)，按照 [C 头文件](include/ctf_ai.h) 实现四个指定函数。这里的接口规定了比赛程序和你的 AI 如何交换数据。
3. 建立自己的代码工程，使用编译器的 release 或优化构建方式生成动态库。创建 `submission/` 文件夹，把准备提交的库保存为 `submission/libteam.so`。
4. 按下面的命令检查 AI 是否能被调用，再进行两场自测。
5. 查看 [比赛回放](docs/replay.md)，找出问题。修改 AI 后使用新的测试目录重新比赛，逐步改进。

以下命令都在解压得到的 `fff-contest/` 文件夹内执行：

```sh
python3 scripts/selftest.py check --out runs/preflight
python3 scripts/selftest.py run --out runs/quick
```

第一条命令检查运行环境，以及比赛程序能否加载、调用你的 AI。通过后再执行第二条：它让你的 AI 与基准 AI 比两场，并交换出生位置。结果分别写入 `runs/preflight/` 和 `runs/quick/`；先看其中的 `report.md`。再次测试时更换目录名，例如 `runs/quick-v2`，工具不会覆盖已有测试。

更多操作见 [自测说明](docs/testing.md)，包括选择地图、比较自己的版本、中断后继续和查看统计。先从这两场了解本机耗时与磁盘用量，再扩大测试。如果改用名单测评工具 `tournament.py` 测试全部 2–8 人名单，`balanced` 方式重复一次就有 **198 场**，该工具默认五次为 **990 场**，可能耗时数小时。`--jobs` 可以设置同时进行的比赛数，但也可能增加 AI 超时；默认及正式评测均为 `--jobs 1`。

## 编译与运行环境

题包中的程序在 **Linux x86_64 GNU/glibc** 环境运行，辅助脚本需要 **Python 3.10 或更新版本**。编译器需要自行准备。`manifest.json` 记录了题包版本、最低 glibc 版本要求，以及用于检查文件是否改变的 SHA-256 值。

你的库需要符合 C ABI，也就是本题约定的函数调用方式和数据在内存中的排列方式。不要求使用 C 语言，也不要求 Rust 编译器与比赛程序使用相同版本。

如果使用 Rust，需要按 C 头文件自行声明相应类型，编译为 `cdylib`，并使用 `#[repr(C)]` 和 `extern "C"`。Rust 2024 的导出函数还需 `#[unsafe(no_mangle)]`。具体要求见 [接口说明](docs/api.md)；题包不提供 Rust 绑定、策略 SDK 或 AI 源码。

提交时以 `submission/libteam.so` 为准。如果它还依赖题包外的其他动态库，请一并向组织者说明；最终文件必须能在比赛机器上加载。

## 使用 LLM 时的开发时限

LLM 的任务时限为 **60 分钟**，包含设计、编码、编译和自测。请时常执行：

```sh
bin/fff-timer-query
```

成功时输出一行 `HH:MM:SS`，表示从场外人员开始计时以来的总用时。例如 `00:12:34` 表示已经过去 12 分 34 秒。这与 AI 在比赛中每回合能计算多久是两回事：比赛第 1 回合为 **250ms**，之后每回合为 **50ms**。

计时器由场外人员启动。LLM 只能查询，禁止启动、停止、暂停、重置计时或修改计时状态。查询失败时请报告场外人员处理。

到 **70 分钟**，场外人员会强制终止 LLM 会话，并收取当时已经编译完成的结果，不等待补编译；**没有编译结果视作弃权**。请在 60 分钟内准备好 `submission/libteam.so`，并在后续修改时保留一份已编译、可提交的版本。纯人类程序员的时间安排由组织者另行约定。

## 题包内容

| 文件夹 | 用途 |
| --- | --- |
| `bin/` | 比赛程序 `fff-runner`、运行 AI 所需的 `fff-ai-worker`、时间查询器 |
| `lib/` | 可用作自测对手的基准 AI |
| `include/` | C 接口头文件 |
| `maps/` | 2–8 队地图 |
| `scripts/` | 自测和统计工具 |
| `viewer/` | 导出、观看回放的工具 |
| `docs/` | 规则、接口、自测和回放说明 |

`fff-ai-worker` 会由比赛程序自动启动，你无需直接运行它。部分游戏细节留给参赛者通过自测与回放探索，实际结果以题包中比赛程序的结算为准。请使用未修改的题包工具进行自测。
