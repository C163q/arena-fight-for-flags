# Fight for Flags：参赛说明

实现一个夺旗 AI 动态库，通过 C ABI 一次控制己方三个棋子。可以使用 Rust、C/C++ 或其他能生成兼容动态库的语言；本题也面向不借助 AI 的人类程序员。

**提交的夺旗 AI 会与其他 LLM/程序员编写的 AI 比拼，他们可能显著强于附带的基准。战胜基准只是参考，请持续测试、分析与改进，提交你能完成的最佳实现。**

## 开始

1. 阅读 [基本规则](docs/rules.md) 和 [完整接口说明](docs/api.md)。唯一接入声明是 [C 头文件](include/ctf_ai.h)，自行编写所用语言的绑定。
2. 创建自己的工程，实现四个 ABI 函数，编译 release 动态库。
3. 创建 `submission/`，把可提交库保存为 `submission/libteam.so`；使用 [自主评测](docs/testing.md) 检查合法性、运行时间和强度。
4. 通过 [回放说明](docs/replay.md) 分析比赛，迭代时保留已编译、可提交的版本。

运行环境为 Linux x86_64 GNU/glibc，Python 辅助工具需 3.10+。`manifest.json` 记录二进制构建信息、最低 glibc 需求、文件哈希和权限。自行准备编译器；采用相同目标平台的 C ABI，不要求 Rust 编译器与裁判相同版本。

Rust 使用 `cdylib`、`#[repr(C)]` 和 `extern "C"`，按头文件自行声明类型和导出函数；Rust 2024 导出符号使用 `#[unsafe(no_mangle)]`。不需要链接项目的 Rust 库，题包不提供策略源码或 SDK。最终 `.so` 应能在比赛机器加载；自带额外动态依赖时需说明。

## LLM 专用时限

LLM 的任务时限为 **60 分钟**，包含设计、编码、编译和自测。必须时常执行：

```sh
bin/fff-timer-query
```

成功输出一行 `HH:MM:SS`。这是总开发时间，与每队每回合 **50ms** 的决策预算不同。计时器由场外人员启动；你只能只读查询，禁止启动、停止、暂停、重置计时或修改计时状态。查询失败时报告场外人员处理。

到 **70 分钟**，场外人员会强制终止 LLM 会话并收取已产生的编译结果，不等待继续生成或补编译；**没有编译结果视作弃权**。请在 60 分钟内准备好 `submission/libteam.so`，并在迭代期间保留可提交的已编译版本。纯人类程序员的时间安排由组织者另行约定。

## 材料

`bin/` 为裁判、worker 和时间查询器，`lib/` 为基准 AI，`maps/` 为 2–8 队地图；`scripts/` 为自测机，`viewer/` 为离线回放工具。游戏中的部分机制需要通过实验探索，文档未穷尽全部规则边界；真实裁判结算为准。不要修改题包工具以制造自测成绩。
