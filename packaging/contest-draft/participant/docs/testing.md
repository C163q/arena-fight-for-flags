# 自测：运行比赛、比较版本与查看结果

先把自己的 AI 编译为 `submission/libteam.so`。本页所有命令都在解压后的 `fff-contest/` 文件夹中执行。

建议按“检查能否运行 → 比两场 → 看回放 → 修改 → 重新测试”的顺序开始。两场比赛不足以确定 AI 的强弱，但可以帮助你发现接入错误、明显的策略问题，以及本机跑比赛需要的时间和磁盘空间。

## 1. 检查 AI 能否运行

```sh
python3 scripts/selftest.py check --out runs/preflight
```

这条命令默认检查 `submission/libteam.so`，分两步进行：

1. 先使用题包自带的基准 AI 运行一次短比赛，检查当前环境能否运行比赛程序。
2. 如果环境检查通过，再加载你的 AI，在只进行两回合的比赛中尝试调用它。

检查用的地图由工具临时生成，不会改动 `maps/` 中的文件。它通过正常的比赛程序加载 AI，因此能够发现库文件加载失败、接口不兼容、崩溃或超时等问题。

完成后先读 `runs/preflight/report.md`；需要进一步排查时查看同目录下的 `diagnostics.json`。如果是你的库无法加载或接口不匹配，请对照 [接口说明](api.md) 检查；如果连基准 AI 都因权限问题无法运行，请把报告交给场外人员处理。再次检查时使用新目录，例如 `--out runs/preflight-v2`。

**检查通过只说明你的 AI 在这两回合中能被调用，不表示它足够强，也不保证在其他局面下不会出错或超时。** 正常比赛中的 AI 故障仍会计入结果。

如果你手动运行命令，阅读报告即可。如果希望自己写脚本，根据检查结果决定下一步，则可以读取命令的“退出码”：这是程序结束时返回给操作系统的整数，不是比赛得分，也不一定会显示在终端上。对这条检查命令，`0` 表示检查通过，`1` 表示检查完成但发现了问题，`2` 表示命令参数、输入文件或执行过程出错。

## 2. 与基准 AI 比两场

```sh
python3 scripts/selftest.py run --out runs/quick
```

默认使用双人地图，让你的 `submission/libteam.so` 与基准 AI 比两场，第二场交换出生位置。两场依次执行，不会同时运行。开始比赛前，终端会显示计划场数。

完成后看 `runs/quick/report.md`。其中列出积分、平均夺旗得分、故障、超时和非法动作等信息；`results.json` 保存便于程序读取的结果。积分只根据完整的一组位置轮换计算；例如默认双人测试要完成两场，才会有该组积分。

这里的“基准 AI”是题包提供的对照对手，不代表其他参赛者的水平。请结合回放理解输赢，不要只看一次测试的积分。

### 换地图、换对手或增加场数

例如，下面的命令在三人地图测试两次完整的出生位置轮换：

```sh
python3 scripts/selftest.py run \
  --map maps/arena_3p.ron --repeats 2 --out runs/three-player
```

默认 `quick` 方式每次让你的 AI 在三个出生位置各比一场，因此这里共 **6 场**。其余两队都使用基准 AI，每队单独运行。常用选项如下：

| 选项 | 作用 |
| --- | --- |
| `--ai 文件路径` | 测试指定库，代替默认的 `submission/libteam.so` |
| `--map 文件路径` | 选择地图；可多次提供，测试多张地图 |
| `--opponent 文件路径` | 用指定 AI 代替基准，填充所有其他队伍 |
| `--repeats N` | 把整组位置轮换重复 N 次，增加随机条件的样本 |
| `--mode balanced` | 增加比赛，使任意两队的相对出生位置也得到均衡安排 |
| `--max-matches N` | 本次最多新增 N 场，剩余部分以后继续 |

同一输出目录只测试创建时的库和地图。工具会保存它们当时的副本；**修改并重新编译 AI 后，请使用新的输出目录**，否则继续测试的仍是旧版本。运行期间不要移动测试目录或替换题包中的比赛程序。

## 3. 比较自己的两个版本

先分别保留两个已经编译好的库，例如 `submission/libold.so` 和 `submission/libnew.so`：

```sh
python3 scripts/selftest.py compare \
  --ai old=submission/libold.so --ai new=submission/libnew.so \
  --out runs/compare
```

`old` 和 `new` 是你为版本起的名字。默认情况下，两个版本各自与基准 AI 比两场，共 **4 场**；它们不会互相对战。可用 `--opponent 文件路径` 更换共同的对手。

对应场次使用相同地图、出生位置和随机种子。随机种子是随机过程的起点；使用相同起点可以减少测试条件的差异，但不同 AI 的操作仍会使后续局面不同，因此这不等于让两版经历完全相同的比赛。

结果写入 `runs/compare/report.md` 和 `results.json`。请同时关注得分、超时、故障以及回放中的表现；多种风格的对手和更多随机样本，比只针对基准测试更有参考价值。

如果需要在新的测试目录中复用这次的随机条件，可加 `--seed-file runs/compare/seeds.json`。它要求地图内容、地图 ID、人数和重复次数与原测试一致。

### 中断后继续

按 Ctrl+C 可以中断测试并保留已完成的记录。继续时运行：

```sh
python3 scripts/selftest.py resume runs/compare --max-matches 2
```

这会校验已完成比赛，再运行最多两场新的比赛；场数限制是所有版本合计。去掉 `--max-matches 2` 就会继续完成剩余计划。继续时使用的仍是创建测试时保存的库，重新编译原文件不会让它改测新版。

## 4. 统计行为与估计磁盘用量

```sh
python3 scripts/selftest.py summary runs/compare --out runs/analysis
```

工具先检查比赛记录是否有效，再生成 `runs/analysis/summary.md` 和 `summary.json`，不会重新运行 AI。可以对一整次自测使用，也可以把 `runs/compare` 换成一场比赛的记录目录。

摘要包括各版本的拾旗、交旗、携旗阵亡、射击结果、友伤、扣血、移动结果和每回合计算用时。阅读时注意：

- 命中次数与实际扣血可能不同。例如多发子弹同时击中只剩 1 血的棋子，命中可以多次，但该棋子只会再失去 1 血。
- 命中率是命中次数除以合法射击次数；移动成功率是实际移动成功次数除以记录中的移动尝试次数。
- 未完成整组位置轮换时，仍可分析已有比赛的行为，但不会据此计算该组积分。

摘要会列出部分事件发生在哪场、哪回合，方便你继续 [查看回放](replay.md)。其中的 `candidate` 指正在测试的你的 AI，`nominal_damage` 指按命中累计的伤害值，`damage_taken` 指棋子实际失去的血量。

摘要还列出当前占用的磁盘空间。若只测试一张地图，可加 `--estimate-matches N`，按已有比赛粗估 N 场的记录用量。少于两场时会提示样本不足，没有样本就不估计；不同比赛的长度不同，估计值不能保证够用。开始大批量测试前，结合实际耗时和剩余磁盘空间安排规模。

## 同时运行多场比赛

`selftest.py run`、`compare`、`resume` 和后文的 `tournament.py run` 都支持 `--jobs N`，表示最多同时进行 N 场比赛。默认是 **1**。例如：

```sh
python3 scripts/selftest.py run --out runs/parallel-check --jobs 2
```

可先尝试 `2`，再根据本机负载与超时情况调整；需要进一步扩大时，可把可用 CPU 核数的一半作为尝试的参考。多场比赛会争用 CPU、内存和磁盘，每回合计算时限仍然不变，因此可能增加超时、改变成绩；也不保证按比例加速，更不会减少回放占用的空间。机器还在运行其他任务，或 AI 已接近计算时限时，应减少同时进行的比赛。

**正式评测固定 `--jobs 1`。** 并行自测适合较快地筛选版本，最终仍应在负载较低、一次一场的环境检查。报告会保留曾使用并行测试的标记；后来改为一次一场继续，也不会清除该标记。需要全程串行的结果时，应创建新测试。

## 保存和恢复比赛记录

```sh
python3 scripts/selftest.py archive runs/compare --out runs/compare.tar.gz
python3 scripts/selftest.py restore runs/compare.tar.gz --out runs/restored
```

第一条将已经全部完成、且没有比赛仍在运行的记录打包保存，原目录保持不变。第二条检查压缩包内容和每场记录后，恢复到新目录；它不会覆盖已有目录，也不会自动删除原始文件。

这项功能用于备份和查看记录，**恢复后的目录不能用来迁移或继续未完成的测试**。恢复后可以选择其中一场比赛，按 [回放说明](replay.md) 重新导出。

默认最多处理 100 万个文件、64GiB 解压数据。确有需要时，可用 `--max-files N`、`--max-bytes N` 调整，后者的单位是字节。摘要工具另有读取限制：最多 25000 帧、单个 JSON 文件 16MiB、每场 JSON 合计 512MiB；超过限制会报错。

## 直接运行一场比赛

如果希望手工指定每支队伍的 AI，可以直接调用比赛程序：

```sh
bin/fff-runner --map maps/arena_2p.ron \
  --ai submission/libteam.so --ai lib/libfff_bot_baseline.so \
  --seed 41 --out runs/my-match
bin/fff-runner verify runs/my-match
```

第一条运行比赛，第二条核对保存的比赛记录。每个 `--ai` 对应一支队伍，按地图队伍编号从 0 开始排列；数量必须等于地图人数。同一个 AI 库也可以用于多支队伍，它们会各自单独运行。

`--seed 41` 固定游戏中的随机起点；AI 自己的随机种子另行生成。需要固定每队 AI 的种子时，可按队伍顺序为每一队提供一个 `--ai-seed N`。即使种子一致，更换策略也可能改变之后的局面。

输出目录必须尚不存在。成功时，终端会输出一行 JSON 格式的比赛摘要；失败时会输出错误信息。回放导出和观看见 [回放说明](replay.md)。

## 使用名单配置进行更多比赛

上面的 `selftest.py` 已能满足常见的开发测试。需要手工指定每种人数的完整参赛名单时，可使用 `scripts/tournament.py`。题包的 `config/tournament.example.json` 已填好“你的 AI + 基准 AI”的自测名单，路径相对于配置文件所在文件夹。

先生成一个仅包含两场双人比赛的计划，再执行它：

```sh
python3 scripts/tournament.py plan --config config/tournament.example.json \
  --out runs/check-new --only 2p --mode quick --repeats 1
python3 scripts/tournament.py run runs/check-new
```

`plan` 只生成计划，不运行比赛。`run` 才开始比赛。若修改配置，每支独立队伍需要不同的 `id`，即使使用的是同一个 AI 库。

`quick` 每次在 N 人地图比 N 场，使各队依次使用每个出生位置。`balanced` 还均衡任意两队的相对出生位置，因此场数更多，例如 8 人地图每次为 56 场。这些安排可以减少位置偏差，但无法完全消除多人对抗中的组合影响。

可用 `--only 3p 8p` 选择名单。**不加 `--only` 会测试 2–8 队：`balanced --repeats 1` 共 198 场，默认五次为 990 场；即使 `quick --repeats 1` 也有 35 场。** 完整测试可能消耗数小时和大量磁盘。先用两场估计代价；LLM 应经常查询 `bin/fff-timer-query`，给编译和提交留下时间。

执行中按 Ctrl+C 可停止，之后重新运行同一条 `run` 命令继续；也可加 `--max-matches 2` 分段进行。**修改 AI 后要新建计划**，旧计划继续使用创建时保存的版本。运行期间不要移动计划目录或替换比赛程序。

结果见输出目录的 `report.md`、`standings.csv` 和 `results.json`。只重新生成报告、不运行比赛时使用：

```sh
python3 scripts/tournament.py report runs/check-new
```

## 怎样理解积分

比赛中的“夺旗得分”和报告中的“积分”不同。夺旗得分是交回旗帜的数量；积分用来概括你相对于其他队伍的表现。

每场对每个对手比较夺旗得分：比对方高记 1，相同记 0.5，低记 0；先取所有对手的平均，再对用于排名的比赛取平均，最后乘以 1000，四舍五入为整数显示。因此积分范围为 **0–1000**，越高越好；它不是赢下比赛的百分比。平均夺旗得分仍按旗帜数量显示，不乘 1000。

只纳入完整且记录校验通过的位置轮换组。排序使用未取整的积分；完全相同时，再比较平均夺旗得分和独胜率。显示整数相同，不一定是并列。置信区间同样按千分制显示，只用于描述这些样本中的不确定性。

报告会为配置中的每一组参赛名单单独列出排名。例如，A、B 的双人比赛与 A、B、C 的三人比赛分别统计，不会合成一张总榜。即使人数相同，A、B 对抗和 A、D 对抗也是两组不同的测试。这里得到的是各组自测成绩，不是所有参赛者的正式总排名。

程序读取结果时，JSON/CSV 的 `score` 是千分制积分，`rank_score` 是对应的 0–1 原始值。比赛程序本身无法运行等问题会停止测试；AI 超时、崩溃等则作为比赛中的故障计入统计。

原始比赛保存在各版本或名单计划目录的 `matches/<场次>/attempt-*/match/`。其中 `attempt-*` 表示一次运行的目录，例如 `attempt-001`。

如果某场比赛中途被中断，续跑时会从头重跑这一场，并新建目录，例如 `attempt-002`；上次未完成的记录也会保留。因此同一场次下可能有多个目录，但未完成的那次不会计入成绩。查看该计划目录中的 `report.md`，在“回放索引”中点击“比赛目录”，即可找到报告实际采用的完整记录，再按 [回放说明](replay.md) 导出。
